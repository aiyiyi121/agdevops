# SxDevOps 用户使用文档

本文面向日常使用 SxDevOps 的运维、研发、SRE 和平台管理员，重点说明 AIOps、可观测性、事件中心、任务中心四个模块的使用方式。

## 使用前准备

1. 使用具备对应权限的账号登录平台。
2. 确认左侧菜单中已开通需要使用的模块权限。
3. 使用 AIOps 前，建议先完成可观测性数据源、事件源、任务资源底座和知识图谱环境配置。
4. 所有执行类动作都应先确认目标环境、系统、资源范围和风险，再提交执行。

## AIOps

AIOps 用于通过自然语言完成运维问答、排障分析、证据汇总、处置建议生成和任务草稿联动。入口位于左侧菜单 `AIOps`，常用页面包括 `智能助手`、`知识图谱`、`智能体配置` 和 `智能体审计`。

### 关键前提：必须配置知识图谱环境

AIOps 问答不是单纯依赖大模型自由回答，而是基于平台内的知识图谱环境进行上下文检索和推理。知识图谱环境必须配置，且配置得越完整，AIOps 问答越可靠。

知识图谱环境会把以下信息组织到同一个环境上下文中：

- 事件中心环境和事件源。
- 指标数据源、日志数据源、链路追踪数据源。
- 告警环境。
- Grafana 看板目录和可观测性跳转关联。
- K8s 集群、Docker 环境。
- 任务中心资源底座环境、主机和 K8s 执行资源。

如果知识图谱环境没有配置，AIOps 可能无法判断用户问题对应哪个环境、系统或服务；如果管理信息不完整，例如缺少日志数据源、事件源、任务资源或环境别名，AIOps 的回答会更依赖有限线索，准确度和可执行性都会下降。

推荐做法：

1. 在 `AIOps / 知识图谱` 中维护环境，例如生产、测试、预发等。
2. 为环境配置常用别名，保证用户提问中的简称能被识别。
3. 关联该环境下的指标、日志、链路、告警、事件、看板和任务资源。
4. 定期检查知识图谱中系统、服务、基础设施和事件之间的关系是否完整。
5. 新增数据源、事件源、集群或任务资源后，同步更新对应知识图谱环境。

### 智能助手

进入 `AIOps / 智能助手`，可以直接用自然语言提问。适合的问题包括：

- “分析生产环境 order-service 最近 30 分钟错误率升高原因。”
- “帮我看一下 payment 服务是否有相关发布或失败事件。”
- “查询某个 trace id 关联的日志，并总结异常链路。”
- “生成一份巡检任务草稿，检查生产环境订单系统主机磁盘和服务状态。”

使用建议：

- 提问时尽量带上环境、系统、服务、时间范围和现象。
- 排障类问题优先说明“什么时候开始”“影响哪个服务”“看到什么告警或错误”。
- 如果需要执行命令或生成任务，先让 AIOps 生成建议或草稿，再由人工确认。
- 对高风险动作，例如重启 Pod、执行命令、扩缩容，应在确认影响范围后再执行。

### 知识图谱

进入 `AIOps / 知识图谱`，先选择环境，再查看图谱关系。图谱用于展示环境、系统、服务、数据源、事件、基础设施和任务资源之间的关系。

常用操作：

- 按环境、系统、服务筛选图谱。
- 查看某个服务关联的日志、链路、指标、事件和资源。
- 识别某个环境下哪些系统或服务缺少观测数据。
- 检查任务资源底座是否覆盖了实际需要执行的主机或 K8s 集群。

### 智能体配置

进入 `AIOps / 智能体配置`，平台管理员可以维护模型、MCP、Skill、Action 和编排能力。

常用配置项：

- 模型提供商：配置 OpenAI Compatible 地址、API Key、默认模型、备用模型、超时和费用单价。
- MCP：配置平台内置或外部工具，并通过白名单限制可用工具。
- Skill：配置不同场景下的专业分析方法、工具依赖、输出格式和风险提示。
- Action：定义用户问题如何路由到告警分析、日志查询、变更关联、任务生成等任务入口。

建议先保证默认模型可用，再启用 MCP 和 Skill；新增外部 MCP 时应限制写操作和超时时间，避免非预期执行。

### 智能体审计

进入 `AIOps / 智能体审计`，可以查看 AIOps 的运行记录。

可查看内容包括：

- 会话历史：谁在什么时间发起过哪些会话。
- 调用审计：Action 命中、Skill 命中和 MCP 工具调用记录。
- 模型调用：模型、Token、耗时、状态和预估费用。
- 待执行动作：待确认、已执行、失败或被策略拦截的动作。

当 AIOps 回答不符合预期时，优先检查审计记录，确认它是否命中了正确的环境、Skill 和工具。

## 可观测性

可观测性用于查询和管理指标、日志、链路、告警和 Grafana 看板，是 AIOps 分析的主要证据来源。入口位于左侧菜单 `可观测性`。

### 可视化与仪表盘

进入 `可观测性 / 可视化`，可以浏览和打开 Grafana 看板。平台支持按目录维护看板，并从看板上下文跳转到日志或链路。

使用建议：

- 将常用业务系统、基础设施、APM、日志排障类看板按目录维护。
- 如果看板无法嵌入，检查 Grafana 是否允许 iframe 嵌入，以及登录鉴权是否可访问。
- 需要从看板跳转到日志或链路时，先维护可观测性关联配置。

### 指标查询

进入 `可观测性 / 指标查询`，选择指标数据源后执行 PromQL 查询。

常用操作：

- 选择 Prometheus 兼容数据源。
- 输入 PromQL 查询接口耗时、错误率、CPU、内存、Pod 重启等指标。
- 使用常用 PromQL 模板快速开始查询。
- 在 `指标数据源` 页签中新增、编辑或停用数据源。

### 日志中心

进入 `可观测性 / 日志中心`，可以查询 ELK、Loki、阿里云 SLS 等日志数据源。

常用操作：

- 选择日志数据源和时间范围。
- 按标签、字段、关键字或查询语句过滤日志。
- 从包含 trace id 的日志跳转到链路追踪。
- 将常用查询条件收藏，或从查询历史恢复条件。

使用建议：

- 排障时先缩小环境、服务和时间窗口，再增加关键字或 trace id。
- 如果查询无结果，检查时间范围、标签名、trace id 字段名和数据源是否匹配。

### 链路追踪

进入 `可观测性 / 链路追踪`，可以查询服务调用链、Trace 明细和拓扑关系。

常用操作：

- 选择链路数据源和服务。
- 按时间范围、Trace ID、服务名查询链路。
- 从 Trace 跳转到关联日志或 Grafana 看板。
- 在数据源页签中维护 SkyWalking、Tempo、Jaeger、Zipkin 等链路数据源。

### 数据源与关联配置

进入 `可观测性 / 数据源` 或 `可观测性 / 关联配置`，维护日志、链路、看板之间的跳转关系。

推荐至少维护：

- 日志数据源和链路数据源的对应关系。
- Trace ID 字段或正则。
- service、namespace、workload 等标签映射。
- Grafana 变量映射。
- 默认跳转时间窗口。

这些关联不仅影响页面互跳，也会成为 AIOps 分析上下文的一部分。

### 告警中心

进入 `可观测性 / 告警中心`，查看平台汇聚的告警信息。告警可作为 AIOps 分析的触发线索，也可以与事件中心、日志和链路一起用于故障复盘。

## 事件中心

事件中心用于沉淀发布、变更、任务、Webhook 外部事件和平台关键操作，按时间线还原排障上下文。入口位于左侧菜单 `事件中心`。

### 事件筛选与时间线

进入 `事件中心 / 事件中心`，先选择环境，再按系统、服务、事件源、结果和时间范围过滤事件。

常用操作：

- 查看某个故障窗口内的事件时间线。
- 按事件分类查看发布、DB 变更、配置变更、运维事务、任务调度等事件。
- 打开事件详情，查看事件源、分类、资源、操作人、结果和扩展信息。
- 对比故障发生前后的发布、变更、任务和外部事件。

使用建议：

- 排障时先确定故障窗口，再查看窗口前后的变更和失败事件。
- 复盘时保留关键事件，便于后续 AIOps 引用和总结。
- 环境、系统、服务字段越规范，事件检索和 AIOps 关联越准确。

### 事件源

进入 `事件中心 / 事件源`，可以查看平台内置事件源和外部接入事件源。

内置事件源通常来自平台自身能力，例如发布、任务中心、K8s、SQL 审计等。外部事件源用于接入第三方系统，例如 Argo CD、CI/CD、GitLab、Jira 或其他自动化平台。

外部事件源接入流程：

1. 创建外部事件源，填写接入名称、接入类型和默认事件分类。
2. 获取平台生成的 Webhook 地址和令牌。
3. 在外部系统中配置 POST 推送。
4. 推送后回到事件中心，按环境、系统、服务和事件源验证入库结果。

删除事件源后，接入地址不可再用，但历史事件不会被删除。

## 任务中心

任务中心用于维护执行资源、下发运维任务、复用任务模板、查看执行结果，并承接 AIOps 生成的待执行任务。入口位于左侧菜单 `任务中心`。

### 资源底座

进入 `任务中心 / 资源底座`，维护任务执行目标和资源分组。资源底座是任务执行和 AIOps 任务生成的基础。

常用对象：

- 环境：例如生产、测试、预发。
- 系统：环境下的业务系统或平台系统。
- 主机资源：主机名、IP、SSH 端口、用户、凭据和状态。
- K8s 资源：关联已有 K8s 集群，作为任务执行目标。

使用建议：

- 先维护环境和系统树，再新增主机或 K8s 执行资源。
- 为资源设置准确状态，异常或停用资源不建议作为执行目标。
- 资源环境应与 AIOps 知识图谱环境保持一致。

### 任务工作台

进入 `任务中心 / 任务工作台`，可以创建、执行和回看任务。

支持的任务类型包括：

- SSH 连通性检查。
- 主机指标刷新。
- 批量命令执行。
- Ansible Playbook 执行。
- 服务状态巡检。
- K8s Pod 重启。
- K8s Pod 命令执行。
- K8s 工作负载伸缩。

常用操作：

- 从资源范围选择目标主机或 K8s 资源。
- 选择任务类型、执行方式和执行策略。
- 使用任务模板复用常见巡检或处置动作。
- 执行后查看每个目标的状态、命令、输出和摘要。
- 对失败任务进行复查或重新执行。

执行建议：

- 批量命令和 K8s 操作前，确认环境、系统、目标数量和命令内容。
- 生产环境优先使用模板和审批过的命令，减少临时输入。
- 对高风险任务先小范围验证，再扩大执行范围。
- 任务结果会进入审计和事件链路，便于后续复盘。

### 计划任务

如果平台已开放 `计划任务` 菜单，可以在 `任务中心 / 计划任务` 中维护周期任务或单次调度。

适合场景：

- 周期巡检。
- 定时采集或刷新。
- 固定窗口内执行的自动化任务。
- 需要保留执行记录的重复性操作。

创建计划任务时，应配置任务类型、目标资源、执行时间或间隔、重叠策略和启用状态。

## 推荐使用流程

一次完整的故障排查可以按下面流程进行：

1. 在可观测性中查看告警、指标、日志和链路，确认故障现象。
2. 在事件中心按环境、系统、服务和时间窗口查看最近变更、发布和任务事件。
3. 在 AIOps 中带上环境、服务、时间范围和现象提问，让智能助手汇总证据和建议。
4. 如果需要执行巡检或处置，由 AIOps 生成任务草稿，或进入任务中心手动创建任务。
5. 人工确认任务范围和风险后执行。
6. 执行结果回到任务中心、事件中心和审计记录中，形成可追踪闭环。

## 使用注意事项

- AIOps 的可靠性取决于平台可用数据和知识图谱环境完整度，不建议把缺少上下文的回答直接作为最终结论。
- 生产环境执行类动作必须经过人工确认。
- 数据源、事件源、资源底座和知识图谱环境应保持同一套环境、系统、服务命名规范。
- 新增系统或服务后，应同步补齐可观测性、事件中心、任务资源和知识图谱配置。
- 排障和复盘时，优先保留可追溯证据：时间窗口、日志、Trace、指标、事件、任务结果和操作人。
